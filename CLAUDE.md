# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A desktop traffic and transit simulation of two connected signalized intersections (Node A at x=1400, Node B at x=3400 on a 4800×2800 px physics surface -- a 500 m link and 350 m on every approach at 0.25 m/px; `canvas_gemini` derives `INT_X`, `H_Y`, `WIDTH`, `HEIGHT` from `LINK_M`, `APPROACH_M` and `PX_PER_M`, so rescaling the network means editing those three; the Tk pane smoothscales the surface, so the world size is independent of the window), built on Pygame (rendered offscreen into a Tk canvas), Tkinter, and an optional separate-process LLM supervisor (LangGraph over local Ollama or the Gemini API). It models demand generation, six fixed bus routes with Transit Signal Priority (TSP) and a Dynamic Bus Lane (DBL), Webster-derived signal timing, conflict-safe intersection entry, and gridlock discharge/recovery. This is a simulation and research tool, not a certified traffic-signal controller — never treat it as one.

## Architecture

### Process topology (current — one Tk process + one LLM subprocess)

`main.py` builds **one** Tk window (`build_main_window()`) with three panes, all in a single process:

- **Left pane** — `control_panel.py`'s Tk controls, mounted via `control_panel.create_dashboard_window(control_pane)`.
- **Center pane** — the simulation: Pygame draws each frame onto an offscreen `pygame.Surface` (no native Pygame window is created), which is pushed into a Tk `Canvas`/`PhotoImage` via `build_simulation_canvas()`.
- **Right pane** — `telemetry_dashboard.TelemetryDashboard`, mounted in-process into the pane rather than run as its own Tk root.

Only `agent.py` (the LLM turn loop) still runs as a separate `subprocess.Popen` child, because model inference latency must never block the 60 Hz simulation loop. One `WM_DELETE_WINDOW` handler on the single real window drives shutdown: it stops the run, terminates the agent subprocess, and triggers the combined Excel export via `atexit`.

Note: `docs/README.md` predates this consolidation in places (it still describes the telemetry dashboard as a separate child process) — trust `main.py` for process topology. `docs/TRAFFIC_SIMULATOR_METHODOLOGY_AND_ARCHITECTURE.md` is the one current description of the model (Part I, paper-ready methodology with every parameter in physical units) and the implementation (Part II); read it before non-trivial changes and keep its constants in step with the source.

### Module ownership (authoritative owner → consumers)

| Concern | Owner | Consumers |
|---|---|---|
| Road geometry | `canvas_gemini.py` | `main.py`, `vehicle.py`, `signal_controller.py`, telemetry |
| Operator configuration (`global_config`, `approach_configs`, `bus_routes_config`) | `control_panel.py` | everything else |
| Vehicle collection & simulation clock | `main.py` | controller, exporter, renderer |
| Vehicle kinematics & route progress | `vehicle.py` | `main.py`, controller, exporter |
| Right-of-way & collision safety | `signal_controller.py` | vehicles, renderer, telemetry |
| Baseline green splits | `webster.py`, applied by `main.py` | controller, telemetry, UI |
| Live state serialization (including network-wide `bus_distribution` by node/approach/route/DBL-lane) | `telemetry_exporter.py` | dashboard, agent |
| LLM output validation | `guard.py` | agent/main merge boundary |
| LLM policy loop | `agent.py` | writes a suggestion only; never moves vehicles |
| Deterministic non-LLM TSP/DBL comparator | `rule_controller.py` | same decision path as the LLM, selected via `ai_runtime["model"]` |
| Real-world unit conversion (display/export only) | `real_world_units.py` | telemetry dashboard, exports |
| Bus TSP/DBL event tracking for export | `bus_event_log.py` | Excel export |

**The central invariant:** the LLM (or the rule comparator) may only *request* route flags. `SignalController` is the sole safety authority — it decides collision checks, all-red clearance, reservations, and spillback protection. Never let a decision source bypass the state machine to set green directly.

### Two independent signal nodes

`SignalController` holds `self.nodes = {node_x: NodeState() for node_x in INT_X}` — Node A and Node B each have their own phase, timer, clearance, reservations, and TSP/DBL request queue, and can diverge under node-local traffic or priority. The legacy `controller.phase`/`controller.timer` properties broadcast setup values to both nodes but are not shared runtime storage; don't reintroduce a shared clock. Normal cycle per node: `EW_GREEN → EW_YELLOW → ALL_RED → NS_GREEN → NS_YELLOW → ALL_RED → repeat`. Priority (TSP/DBL) is a request that flows through its own state machine (`NORMAL → REQUESTED → CONFLICT_YELLOW → ALL_RED_CLEARANCE → PRIORITY_ACTIVE → PRIORITY_CLEARING → RECOVERY_ALL_RED → NORMAL`), never a direct phase assignment.

**A blocked green is deliberately NOT cut short.** Truncating a green once its receiving lanes have spilled back was implemented and measured (2026-09-22, seed 234, 15 min, benchmark regime): it served 8,350 pax against 8,960 untreated, 6.8 % worse, with more vehicles standing at the end. It removes the green from the movement that discharges first when the downstream clears, and hands the time to a cross street feeding the same saturated box. A saturated corridor wants offset/coordination between the nodes, not phase truncation. `vehicle.ENTRY_ZONE_PX` is the one entry-zone constant (the reservation/keep-clear radius in `Vehicle.update`); keep any new stop-bar check reading it rather than a fresh literal.

### Cross-process data contract (agent.py ⇄ main.py)

- `ai_control.json` (written by `control_panel.py`, read by `agent.py`) — armed state, selected model/rule, tick interval, sim-running flag.
- `traffic_state_telemetry.json` (written atomically by `telemetry_exporter.py`, read by dashboard and agent) — the authoritative snapshot.
- `decision.json` (written by `agent.py`/`guard.py`, read by `main.py`) — the latest guarded, canonical (route-ID-keyed) TSP/DBL flags.
- `telemetry_log.jsonl`, `agent_turn_log.jsonl`, `agent_rejects.log`, `bus_events.jsonl` — append-only observability logs consumed by exports.

All of these plus `excel_exports/*.xlsx` are runtime-generated, gitignored, and use atomic replace (`os.replace` after writing to a temp file) so a reader never observes a half-written file. `main.py` rejects a `decision.json` whose timestamp is missing, invalid, or older than `max(3 * agent_tick_seconds, 12s)`, and falls back to all-off. It also rejects one that was not made for this run: telemetry carries `run_uuid` (fresh on every `perform_full_reset`), the agent's single writer `agent.publish_decision` stamps it (plus `telemetry_frame`) into every decision, and `merge_ai_decision` requires `run_uuid` and `model` to match the live run/selection (`FOREIGN_DECISION`) and refuses a turn older than the last merged one (`STALE_DECISION`); every key `run_forever` puts into the graph state must be declared on `agent.AgentState` — LangGraph silently drops undeclared keys on `invoke`, which once left `run_uuid`/`telemetry_frame` empty and every live decision refused as `FOREIGN_DECISION` while the unit tests (plain-dict states) stayed green, so `test_llm_control_loop` now asserts the identity through the compiled graph; a full reset of a timed run clears every route flag for every arm and restarts `last_turn`. `main.main()` also takes an OS lock on `data/simulator.lock` so two simulators can never share these files. **Model output is untrusted**: `guard.py` accepts only two boolean lists of exactly the canonical route count (`ROUTE_ORDER = sorted(control_panel.bus_routes_config.keys())`); anything else (wrong length, non-bool, malformed JSON, exceptions) becomes a complete all-off `HELD_ALL_OFF` decision, logged to `agent_rejects.log`. Preserve this fail-closed behavior in any change to the LLM/rule path.

### Run lifecycle

- **START** — full reset (clears vehicles/controller/logs/throughput/spawner state), recalibrates saturation flow and Webster splits, applies seed/speed, begins at frame 0. Shared helper: `perform_full_reset(vehicles, signals, telemetry)`.
- **STOP** — halts stepping but preserves vehicles/logs/throughput for export.
- **PAUSE/RESUME** — freezes/resumes in place.
- **RESET** — same full-reset helper as START.

Physics is a fixed 60 Hz step (`dt_step = 1/60`); `sim_speed` controls how many fixed steps run per wall-clock tick (bounded catch-up), not the timestep itself. Every tick (`TICK_MS`, re-armed against the tick's start so its own work never stretches the period) paints a frame only when `build_simulation_canvas`'s `frame_is_due()` says so, and that one gate covers the network draw and the `get_all_dbl_states` scan as well as the push, so a skipped tick costs nothing instead of drawing a frame it throws away; vehicles are drawn by the push at the position interpolated between the last two physics steps (`Vehicle.render_position`, `alpha = time_accumulator / dt_step`), and when the view is zoomed past one screen px per world px they are drawn straight onto the scaled frame so fractional world positions land on their own screen pixel. Frames above `FULL_RATE_PUSH_MAX_PIXELS` (maximized on 1080p) are pushed every other tick because Tk's PhotoImage paint costs ~14 ms/MP, and while `batch_runtime["active"]` is set it drops to one painted frame per `BATCH_RENDER_INTERVAL_SEC` (1 s of wall clock, not a tick count, because a tick's length follows the load): on the 500 m network a painted frame costs ~25 ms and physics ~86 % of the wall clock, so 1 fps holds rendering near 2.5 %, where every 15th tick was 6-9 %. Rendering is display-only, like the zoom — never let telemetry, the agent or a metric read `frame_is_due`. A source more than twice the pane's width is shrunk in two stages (`main._downscale`: nearest-neighbour to twice the target, then smoothscale) -- 6.8 ms against 15 ms for the 4800 × 2800 surface, 2/255 mean pixel difference -- and layout reads `CANVAS_DISPLAY_HEIGHT` (the pane at display width, floored at the 600 px the window was designed around), never the native `canvas.HEIGHT`.

### Movement model (`vehicle.py`)

One following law, `Vehicle.follow_target_speed`: stop under `SAFE_GAP_PX` (12), follow at gap/30 × own desired speed up to `FOLLOW_FREE_GAP_PX` (37), free flow beyond; kinematics ramp ±0.05/frame *toward* it in both directions (a queued vehicle pulls away as soon as its leader does). Straight cars make MOBIL-lite discretionary lane changes between lanes 0 and 1 only (lane 2 is the left-turn/DBL lane): incentive is follow-speed gain as a fraction of the driver's own heterogeneous desired speed (inward needs +20 %, outward may lose 10 % — keep-outer), safety is nobody alongside in the target lane and ≥ 30 px behind, considered with a 1/120 per-frame hazard from the run-seeded RNG. No per-lane speed cap: the travel-delay DV measures against each vehicle's own `max_speed`. All cooperative slides (`step_lane_vacate`) check only the target lane band, and a vehicle *behind* the mover that already overlaps its y-band is a follower, not a lateral blocker (`vehicle._is_following`): the following law parks it at `SAFE_GAP_PX` (12), under the 15 px "alongside" margin, so counting it would freeze every mid-slide vehicle whose follower caught up — the live WB deadlock of 2026-09-21 (a left-turning truck straddling lanes 1/2 at Node A with an empty bar ahead). **Neighbour queries go through a per-frame index.** `get_lead_vehicle`, `should_yield_for_route_merge` and `dbl_merge_bus_blocked_by` each ran once per vehicle per frame and each walked the whole list: at ~230 vehicles that was O(n^2) and 21.0 ms per frame against a 16.67 ms budget, so a 15-minute run took 28 minutes of wall clock. `vehicle._FrameIndex` is a uniform grid rebuilt once per frame — `main.step_simulation` drops it at the top (`index_frame(None)`), rebuilds it after the frame's spawns and dispatches (`index_frame(vehicles)`) and tells it about mid-frame removals (`drop_from_index`) — taking the frame to 8.2 ms. The index also memoises `receiving_space_px` per (node, exit lane) for the frame (`_FrameIndex.receiving`, cleared by `drop`): the metrics pass asks it for every vehicle upstream of a bar, and with snapshot reads that alone was 24 ms per frame at 200 vehicles (2026-09-23); a campaign-demand frame on IDM now costs 11.4 ms. On the 500 m network (2026-09-24) two more accelerators took a frame at ~400 vehicles from 18.5 to 14.5 ms, bit-identical by the golden fingerprints: `_lead_from_index` judges each candidate once and returns the leader (it used to hand the candidates back for a second `_gap_ahead` pass, every gap computed twice; ties still go to the earlier list position), and `_FrameIndex.standing_in(direction)` groups the frame-start standing vehicles so `_receiving_scan` walks those instead of the whole list (a mid-frame `drop` removes the vehicle from its group). `should_yield_for_route_merge` looks for a merging bus before the intersection geometry. **It is a candidate filter and nothing more**: every query re-applies its original predicate (`_gap_ahead` is the single copy of get_lead_vehicle's test) in original list order, lookups are padded by a `margin` of the largest half-extent plus the largest speed on the surface so within-frame movement can never hide a candidate, cell walks are bounded by the occupied cell range rather than the canvas (a vehicle lives 60 px past the surface before removal), and a list the index was not built from falls back to the full scan. `vehicle.USE_FRAME_INDEX = False` forces the scan; `tests/test_frame_index.py` asserts whole runs are identical either way, so a change here must stay a pure accelerator — it re-pins nothing, and if it ever changes a result it is a bug, not a new model. `vehicle.lane_changes_suspended()` wraps the single-lane saturation calibrators, and `movement_model_signature()` is part of `config_hash`. See `docs/audits/2026-09-20-bus-stalls-on-green-and-lane-changes.md`.

**Two movement engines, one physical scale.** `vehicle.METERS_PER_PX` (0.25, the same figure `real_world_units.meters_per_pixel()` derives from HCM jam spacing; a test pins them together) and `FPS` are the only unit anchors, with `mps_to_px_per_frame` / `mps2_to_px_per_frame2` converters. `global_config["movement_model"]` picks the engine at `perform_full_reset` (before saturation flow is measured, so S and Webster describe the engine that drives) and it is in `movement_model_signature` / `config_hash` and the `movement_model` summary column, so runs from different engines never pair. `"idm"` is the **default** (flipped 2026-09-23, with a re-pinned suite and golden outputs). `"legacy"` is the gap/speed rule above with its ±0.05 px/frame² ramp (45 m/s² at scale) and 0.5 px/frame slide (0.7 s per lane, 7.5 m/s lateral); it is kept **for comparison only** and must not produce benchmark results: with stalled headways excluded its uninterrupted saturation flow is ~2,800 veh/h/lane at speed scale 0.6 (HCM base 1,900), 470 of its braking events per vehicle-hour exceed 2 g, and its absolute 0.5 px/frame "standing" threshold makes any truck slower than 27 km/h read as spillback, stalling the queue behind it for up to 20 s. Every campaign up to 2026-09-22 ran on it. `"idm"` is the Intelligent Driver Model per vehicle class (`IDM_PARAMS_MPS`: car T 1.0 s / a 2.0 / b 2.0 m/s², truck 1.7 / 0.8 / 1.5, bus 1.5 / 1.2 / 1.5; s0 = `SAFE_GAP_PX` = 3 m so the jam-spacing anchor holds; v0 = own `max_speed`), braking at its comfortable rate to a red/yellow bar, a hold point or a full receiving lane (`bar_obstacle_gap` / `hold_gap` in `Vehicle.update`, `_idm_step`) instead of the legacy hard stop inside 15–25 px, full MOBIL discretionary changes (`choose_discretionary_lane_mobil`: follower safety −4 m/s², politeness 0.3, threshold 0.1, keep-outer bias 0.3 m/s²), a 3 s lane change (`LANE_CHANGE_DURATION_S`, through `lane_change_step_px()` which every slide and the bus merge use) and a 1.5 m/s standing threshold (`slow_vehicle_speed()`; the legacy 0.5 px/frame is 27 km/h and made a discharging IDM queue read as spillback). `tests/test_physical_calibration.py` pins it against reference values: S from the production calibrator 1,913–1,939 veh/hr/lane cars-only at speed scale 1.0 (HCM 1,900) and ~1,480 at the default 0.5 scale (32 km/h free flow); 0→v0 in 4–12 s; peak braking ≤ b; queue spacing 7.5 m; queue-tail shockwave −6 to −20 km/h; lane change 3 s; MOBIL safety and politeness; a headless network soak with no overlaps. Entry reservations are booked at 25 px, but an IDM vehicle inside its braking distance asks the controller first (`SignalController.entry_would_be_granted`, side-effect free) and brakes comfortably for a box that will not open. Tests written against legacy asserted one-frame stops from 15 m/s (~90 g); they now assert the mechanism (no reservation, no crossing, no entry) over a physical stop — keep it that way, never re-assert an instantaneous stop.

Turning movements per approach are `turn_split` (straight) plus `left_far_share` (the second left option in `control_panel.APPROACH_TURN_OPTIONS`: EB/WB left at the far node, A_SB/B_NB a double left; A_NB/B_SB have none), set on one two-thumb `SplitBar`. The spawner gives each car `left_nodes`, and `Vehicle.update` derives `target_turn` per leg from it; a car turning left at a node it is approaching moves into lane 2 within `TURN_LANE_MERGE_PX` (250) and holds at the bar until it is, and DBL evictions leave it there. Add a turning option in that one table, never in the spawner.

The sim pane zooms (mouse wheel; left- or middle-drag to pan; double-click to reset — bound on the canvas widget, so it works in every window shape) by cropping the physics surface before the smoothscale in `build_simulation_canvas`; it is display-only and invisible to telemetry and the agent.

### Passenger-throughput objective

This simulates passenger throughput, not just vehicle count: a car carries 4 passengers, a truck 1, a bus 45 (`vehicle.py`). Throughput is credited only when a vehicle exits the screen *and* its `passed_nodes` set is non-empty; `passed_nodes` is only marked once a vehicle's rear has cleared the conflict box (not at the stop bar or vehicle center). Preserve this distinction — don't collapse it to a simple vehicle count.

### Six bus routes and DBL/TSP

Routes are defined once in `control_panel.bus_routes_config` (`R1_EB_A_NB`, `R2_EB_B_NB`, `R3_EB_ONLY`, `R4_WB_A_SB`, `R5_WB_B_SB`, `R6_WB_ONLY`; R3/R6 disabled by default). A DBL-eligible bus must have its route flag enabled, be approaching the correct leg/node, occupy the required DBL lane (lane index 2), and be within the configured eligibility distance — `SignalController` is the sole authoritative answer for eligibility, used by both priority requests and bus lane migration. DBL merges that are optional may be abandoned after a bounded wait (DBL must never leave a bus worse off than baseline); route-required merges are never abandoned since the bus needs that lane to complete its route safely.

A DBL request/grant is additionally vetoed whenever `vehicle.dbl_lane_is_obstructed(...)` reports a stopped or crawling vehicle ahead of the bus in the reserved lane (`vehicle.dbl_lane_queue_ahead`), even once the bus is already sitting in that lane — this is the fix for the bus-stuck-with-a-clear-lane bug: clearing a non-bus vehicle out of the DBL lane is now unconditional (not gated by proximity to the bus), so a car far ahead, or a car that entered the lane after the bus did, still gets told to vacate. A leg vetoed this way sets `dbl_merge_abandoned_for_leg` immediately and stickily, instead of waiting out the usual bounded-abandon timer, so the bus does not oscillate between requesting and creeping. **A bus ahead in the reserved lane is never an obstruction** (`dbl_lane_queue_ahead` skips `Bus` instances): it is the lane's intended occupant and clears under its own priority. Counting one vetoed the follower stickily, so wherever several routes share an approach — EB lane 2 at Node A carries R1, R2 and R3; at Node B, R2 and R3 — only the leading bus of a platoon could ever hold the lane. A stopped car in the same place still vetoes. The same lane check is re-run every frame the request lives (`SignalController._request_is_live`): a vehicle the gate accepted while moving that later stands ahead of the bus in lane 2 (a permissive left waiting for a reservation, a spillback hold) revokes DBL with `DBL_REVOKED_LANE_BLOCKED` — the request ends if it was DBL-only, else it carries on as plain TSP with `dbl_revoke_reason` set. Left turners are the one general movement that must use lane 2, so while DBL is active on their approach they hold in their general lane at the bar (`must_hold_for_lane` without a `lane_vacate_target`) rather than enter the reserved lane; new left-turn arrivals are retained at the source. `rule_controller.py` and `agent.py`'s system prompt were updated in lockstep to treat a non-zero `dbl_lane_queue_ahead` as a hard veto, and `agent.py`'s `anti_cheat` step forces `dbl=False` server-side for any new (non-locked) grant when telemetry shows the obstruction, so a model cannot bypass this safety property even by ignoring the prompt.

### Early-green arrival gate, warm-up discard, baseline arm

`SignalController._early_green_is_feasible` gates every red truncation: the cut must exceed `yellow + all_red`, and the bus's predicted stop-bar crossing (`max(eta, green start)`, ETA from the shared `vehicle.bus_eta_frames` — under IDM the *unimpeded* kinematic arrival time (accelerate from the current speed to desired speed at the class a₀, then cruise), how deployed TSP predicts arrival from a check-in point; the current-speed estimate badly overstated it for a bus slowing for the red it was asking to cut; the same estimator telemetry, the bus event log and the comparators read) must fall inside the green the cut brings forward. `tests/test_signal_priority.py::test_t2b_*` pins the converse: a slow bus that cannot reach the advanced green is withheld. A withheld request stays `ARMED` and is re-checked each frame; a bus that crosses untreated finishes `DENIED` with the gate reason. The extension has the twin gate (`_extension_is_feasible`): the green is held only when the bus's ETA at its current speed fits inside the cap (`0.2 × green`); otherwise the green ends on time and the request stays armed for an early green. Before this gate, any armed bus in the zone triggered an extension when the green expired, and with buses at 0.5 px/frame and a 265-frame cap every bus more than ~130 px out met the red at the end of the held green anyway — the T6 batch pin of a 0-frame median extension wait was only ever a knife-edge (19 of 36 extended crossings at 0, the rest hundreds of frames) that the 200 m link tipped over. `priority_eligibility_px` defaults to 400 px (100 m); the panel slider runs 62.5-350 m (`PRIORITY_ELIGIBILITY_UI_MIN/MAX_PX`) and the controller clamps it to the link between nodes (`INT_X[1] - INT_X[0]`, 2000 px = 500 m at 0.25 m/px). A second gate, re-checked every frame in `_request_can_start_tsp`, refuses any timing change while the bus's receiving lane cannot take it (`TSP_DENY_DOWNSTREAM_BLOCKED`): `vehicle.receiving_space_px(node, direction, movement, lane, vehicles)` is the one receiving-space measure — free road in the *specific lane the movement enters* (straight keeps its lane; a left turn lands on the exit road's lane 2), from the conflict box to the tail of the nearest standing vehicle — read by the vehicle's spillback hold at the bar, this gate, telemetry (`downstream_space_m_by_lane`, per-bus `receiving_blocked`/`receiving_space_m`) and, through the per-bus field, the rule and max-pressure comparators. The approach-level `downstream_space_m` is the best lane and `downstream_blocked` means every lane is blocked; never gate a bus on those, they average away a full target lane. See `docs/audits/2026-09-20-tsp-early-green-mistiming.md` — and note that comparing `early_green` crossings against `none` crossings is a selection artefact (red-arrivals vs green-arrivals); compare arms on paired seeds instead. `src/experiments/headless_run.py` runs the same engine without Tk for that purpose (`TSP_BATCH_TESTS=1` enables the seed-batch regression): one frame of the simulation is `main.step_simulation(vehicles, signals, frame, decide)` — spawn/dispatch, decision merge, controller, vehicles with crossings/completions/throughput/bus events, per-frame metrics, warm-up snapshot — and both the Tk callback and `headless_run.run` call it and nothing else (`tests/test_step_equivalence.py` enforces this from the source and by fingerprinting a whole run). Never put simulation logic in the Tk loop or re-implement the frame headless; supply a different `decide(frame)` instead.

`converged` needs both the cumulative pax/min (within 5 % between 0.8 T and T) and `vehicles_in_network` (within 10 %) flat — a cumulative mean alone flagged still-loading runs; `delay_sec_per_pax_served_steady` is the demand-normalised DV for cross-arm tables. The workbook carries the operator inputs twice: `Control Panel Inputs` at export (in an assisted run its per-route flags are the decider's last decision) and `Control Panel Inputs (start)` from the snapshot `perform_full_reset` stores in `global_config["_initial_input_rows"]`, which is the run's verifiable setup. `perform_full_reset` also unlinks `decision.json` and clears `last_status`, so a run opens `WAITING_FOR_DECISION` rather than refusing the previous arm's file as `FOREIGN_DECISION` until its first turn. `bus_events.jsonl` node records name every requested-but-untreated outcome (`denial_reason` falls back to the terminal state, e.g. `COMPLETED` = crossed on its own) and keep DBL apart: `dbl_requested` / `dbl_denial_reason` (revocations and a DBL-only request's terminal reason), with `tsp_requested`/`dbl_requested` sticky across a bus's successive requests at one node. Every steady-state DV in `experiment_summary_<YYYYMMDD>.csv` (`main.experiment_summary_path()`, dated by the day the campaign started so a batch crossing midnight stays in one file; `paired_dv_<campaign>.csv` sits beside it) (`pax_per_min_steady`, `*_delay_steady`, `converged`) discards `global_config["warmup_discard_frames"]` (default 18000 = 300 s, about 2.5 crossings of the 1.2 km arterial; 120 s on the old 600 m network) via the snapshot `main.snapshot_warmup_baseline` takes once per run; the cumulative columns stay as they were. Default benchmark duration is 60 min. A summary CSV whose header no longer matches is rotated, never appended to ragged.

**Primary DV** is `total_person_hours_delay_incl_entry_steady`: passenger-weighted time below each vehicle's own `max_speed` (so crawl counts, not just stops) **plus** the time offered demand waited at the network boundary for the entry to clear (`car/bus_passenger_entry_wait_frames`, exposure per frame; per trip `entry_delay_frames`, SUMO's departDelay). Campaign 2026-09-22 served 58-62 % of the vehicles it offered and none of the rest's wait was in any DV, so an arm that admitted less traffic looked better per vehicle; in a measured pair the on-road DV improved 0.41 pax-h while the uncounted entry wait grew ~4.8. The on-road figure stays as `total_person_hours_travel_delay_steady` / `net_person_hours_saved_on_road`. It is compared as a paired per-seed difference against the baseline arm: `main.pair_against_baseline` writes `paired_dv_<campaign_id>.csv` (`net_person_hours_saved = baseline − arm`, with bus/car split and the stopped-delay variant) at batch end. No per-run column may claim "net saved" — the baseline is another run — which is why the earlier `net_person_hours_saved` column (TSP adjust seconds × 45 pax minus TSP-window cross-street delay, zero for baseline by construction) was removed; `tsp_window_cross_street_person_hours` remains as a descriptive mechanism column only.

**Webster demand.** `webster.compute_all_nodes` evaluates each node on a node-by-node movement matrix (`webster.movement_lane_flows`): every (approach, turn option) of `control_panel.APPROACH_TURN_OPTIONS` is walked node to node with the lane `vehicle.py` gives it -- straight from the source spread over lanes 0/1, a left from lane 2 at the node it turns at (a far-node left passes the near node in lanes 0/1), and after any left the car lands on the exit road's lane 2 and keeps it to the next node, so a B_NB/A_SB left loads the corridor's lane 2 at the *other* node. `critical_lane_flows` takes the heaviest lane per phase per node, and the Units tab / `vc_ratio` use `approach_critical_lane_flow_veh_hr` (the approach's own entry direction, busiest lane at any node it enters) so v/c and Webster's y agree by construction. An inactive approach offers nothing. Add a turning option in that one table and the matrix follows; never re-derive a lane share from `turn_split` alone.

**Delay cohorts.** `network_throughput`'s `*_delay_frames` / `stopped_vehicle_frames` counters are network exposure: every vehicle in the network, every frame, finished or not (that is what the person-hours DVs are meant to be). Every per-vehicle or per-passenger *mean* (`mean_stopped_delay_sec_per_vehicle`, `mean_bus/car_passenger_delay_sec`, their `_steady` variants, `node_*_mean_delay_sec`, and the live telemetry) divides the `completed_*` counters `_record_completed_vehicle_delay` fills (`node_completed_stopped_frames` at the crossing) by the served count, never the exposure counters -- an unfinished vehicle in the numerator but not the denominator inflates an early or congested checkpoint. The censored remainder is reported apart as `unfinished_stopped_person_hours` (exposure minus completed) and `passenger_hours_in_network`. `level_of_service` reads `mean_control_delay_sec_per_vehicle`: arrival-to-departure time lost below the vehicle's own free-flow speed over its whole route (`_experiment_travel_delay_frames`, so both nodes for through traffic -- conservative against a per-intersection HCM grade); stopped delay is labelled a proxy and no longer grades LOS.

**Source queues, crawl thresholds.** Bus departures are trips, not a flag: `main.check_and_dispatch_buses` appends one pending trip per elapsed headway (and one per manual dispatch) to `main.bus_pending_trips[route]`, so several departures due while the entry is blocked accumulate and leave in order; each trip a blocked entry holds is counted once in `bus_trips_missed`, and the dispatch record carries `scheduled_departure_s`, `actual_departure_s`, `source_delay_s`, `pending_trips_at_departure` (also in `bus_event_log` and the `bus_trips_scheduled/pending/missed`, `bus_source_delay_sec` summary columns). A DBL queue (`vehicle._is_queued_for_dbl`) is a vehicle standing (≤ 0.05 px/frame) or at ≤ 35 % of its own `max_speed` with a leader within `3 × SAFE_GAP_PX` — never an absolute speed, because 0.5 px/frame is a bus's free-flow speed. The gridlock monitor counts crawling (≤ `GRIDLOCK_CRAWL_SPEED_PX_PER_FRAME` = 0.1) as stopped and its `--watch` loop keeps one monitor across samples, so onset/clearance are sustained. The pressure arm is named `passenger-pressure-tsp` (`control_panel.MAX_PRESSURE_MODEL`) because it is a TSP gate, not a phase-selecting max-pressure controller. Every recurring Tk `after()` in the control panel is tracked and cancelled on `<Destroy>`; `docs/NETWORK_GEOMETRY.md` is generated from `canvas_gemini` by `docs/generate_geometry_tables.py`, never hand-edited; `tests/test_adversarial_simulation.py` asserts all-pair and swept (before→after tick) non-overlap, not just cross-direction pairs.

**Export filenames carry the control mode.** `build_excel_export_filename` names a workbook `model[-mode]_runtime_seed_DDMMYYYY_HHMMSS.xlsx`, and the `_gridlock.xlsx` sidecar follows it. An LLM is the only decider that can run either way, so only an LLM arm carries the mode -- `llama3-1-8b-assisted` against `llama3-1-8b-configured` -- and the word is the `control_mode` summary column's, so a workbook joins to its CSV row. Baseline and the rule comparators name themselves and are always assisted, so their filenames are unchanged. The mode comes from `test_control_mode` (captured at test start, so a checkpoint cannot re-read a panel changed mid-run); the untimed session workbook uses the live `ai_runtime` mode. Before this, the two modes of one model differed only in their timestamp (`results/orca-mini-7b_10min_234seed_*.xlsx`, 2026-09-22).

**Checkpoints land on their own frame.** The fixed-step loop breaks at `main.at_export_boundary`, so an export never happens mid catch-up burst. It used to run the whole burst first and only then look, overshooting each mark by a per-run 0-5 frames; `demand_draw_hash` is a running digest read at export, so an arm that overshot by 3 frames hashed in one more arrival than one that overshot by 2 and the pair was refused on demand that was in fact identical (campaign 2026-09-22: 29 of 33 refused, 4 pairs formed). Keep any new export on this boundary.

**Pairing contract.** A pair is formed only within one campaign and only when the two rows agree on every `main.PAIRING_MUST_MATCH` column (`config_hash`, `git_sha`, `demand_draw_hash`, `checkpoint_min`, `test_duration_min`); anything else is listed as refused with the differing columns. `config_hash` is the regime frozen once per run at the end of `perform_full_reset` (`global_config["_regime_hash"]`, after calibration) and deliberately excludes treatment — a route's `tsp_enabled`/`dbl_enabled`/`manual_dispatch` are what the arm does (the `model`/`llm_*` columns), never part of the regime — so a checkpoint can never re-hash a live panel into a different regime mid-run.

**Common random numbers.** Demand is exogenous: every source (`spawner_states[key]`) has its own `random.Random` stream seeded from the run seed (`main.seed_demand_streams`), each offered arrival is drawn complete (turn, lane, type, speed, color) at offer time by `_draw_arrival` and queued at the source (`state["arrivals"]`, capped at `MAX_PENDING_ARRIVALS` with overflow counted) until the entry is clear, and `demand_draw_hash` fingerprints the offered schedule (source, offer frame, attributes) **through the row's own mark**, not through whatever had accumulated when the export ran (`_demand_draw_hash_hex(up_to_frame=...)`, over `_demand_draw_state["offers"]`). A rolling digest read at export made the fingerprint depend on the frame the export landed on: campaign 2026-09-22 split every seed into two groups one offered car apart (2803 vs 2802 at seed 234) on demand headless proves identical, and 13 of 29 arms were refused. The 5- and 10-minute checkpoints agreed exactly and only the final export drifted, so `export_frame` is now a column -- if it ever differs from the mark, the windowed loop overshot and that is the bug to chase, not the hash. `reset_traffic_generation` (called AFTER `calibrate_and_apply_webster`, never before) clears the fingerprint and restarts `vehicle.reset_vehicle_serials()`, because the calibrator spawns through the same sources and is setup, not the run. Behavioural draws (`vehicle.py`'s lane-change hazard) come from each vehicle's own `behaviour_rng` (`main.behaviour_stream`, keyed on run seed plus the vehicle's exogenous identity: source and arrival index, or route and trip), and dwells from a per-(route, trip) stream, so neither the update order nor a controller arm that changes congestion can change what any source offers, how any given vehicle draws, or how long any bus dwells; and `pair_against_baseline` refuses a pair whose `demand_draw_hash` differs. Never draw vehicle attributes at admission time or from the global RNG again, and keep `DEMAND_MODEL_SIGNATURE` in `config_hash` bumped when the generator changes.

**Decisions are released on the simulation clock, so pace no longer has to be 1.0.** `decision_lag_seconds`, `eta_at_decision_land`, `latency_to_cycle_ratio` and the staleness window all spend a wall-clock model latency against sim time. They used to be correct only at a pace of 1.0 (campaign 2026-09-22 ran at 0.53 and every arm's real control delay was about half its horizon, confounded with the arm because a slow local model also slows the sim). On the 500 m network a frame costs 23-28 ms at 0.6x demand (~500 vehicles) and 37-42 ms at campaign demand (~780), so 1.0 cannot be held. Instead the agent stamps each decision with its snapshot frame and the call's `latency_ms` (`agent.publish_decision`), and `merge_ai_decision` holds a new turn as `PENDING_RELEASE` until `main._decision_release_frame` = snapshot frame + latency in frames (checked every frame while pending), with the decision in force staying in force; staleness is judged in sim time from the snapshot frame. The agent's skip accounting uses the same rule: a turn occupies the schedule until `agent.turn_busy_until` (decided-at + real latency, or the sim time reached when the call returned, whichever is later), so a slow model skips the grid points it would skip in real time even while the sim runs slower than real time. The sim-time control delay then equals the measured latency at any pace, and a slow pace only costs wall time (a 60-minute run at 0.6x demand takes ~100 minutes). A pace **above** 1.0 would still land decisions late, so never raise `sim_speed` above 1.0 for a measured campaign; `print_campaign_summary` names any run above `1 + PACE_TOLERANCE`. `main._pace_state` accumulates unclamped wall time and `sim_seconds_per_wall_second` reports it per row; both reset branches of the Tk loop re-stamp `last_wall_time` after `perform_full_reset`. The control delay each decision actually suffered is **measured on the sim clock**, not inferred: the agent stamps the decision with the frame of the snapshot it decided on (`load_save` returns `telemetry_frame`), `merge_ai_decision` records the first frame the turn took effect (`_record_decision_applied`, `run_metrics["decision_applied"]`), and the difference -- grid-point detection (telemetry every 10th tick, agent poll 0.2 s), the model call and the release -- is the audit sheet's `control_delay_sim_s` and the summary's `control_delay_sim_sec_median/_p95`. Cite those, not `decision_lag_sec_used` (wall latency). The telemetry file is written compact (`json.dumps`, C encoder): `json.dump(indent=2)` took 14 ms per export at 200 vehicles on the tick that paces the sim.

**A local model shares the machine with the sim.** Three settings keep both working, all measured 2026-09-23 (Ryzen 7 5800X 8C/16T, RTX 3070 8 GB, Ollama 0.34): `main.raise_simulator_priority()` puts the sim process at above-normal priority (its one thread gets a core first); `agent.OLLAMA_NUM_THREAD` leaves `SIM_RESERVED_CORES` (2) physical cores to it (`OLLAMA_NUM_THREAD` env overrides, for hybrid CPUs); and `agent.OLLAMA_NUM_CTX` = 8192 fixes every model's context window. The last one matters most: Ollama otherwise sizes the window from the model's maximum (65,536 for llama3.2:3b, a 10 GB allocation), so small models spilled 42-81 % onto the CPU, ran 5-17 s a turn and slowed the sim's frame 1.4-1.6x; at 8k llama3.2:3b, phi3:3.8b, llama3:latest and llama3.1:8b are 100 % GPU at a 0.7-1.7 s median with the frame within budget. A prompt that fills the model's real window (`model_context_tokens`: 8k capped at the model's native maximum) fails closed -- Ollama truncates silently and the model still emits valid JSON. Reasoning models (gemma4, nemotron-3-nano) spend 1,300-2,300 hidden tokens a turn and time out; the benchmark and drop decision are in the methodology's decision-arms section.

**S is measured on the standing queue, so it describes the regime, not the network size.** `calibrate_saturation_flow` times only the vehicles standing in the queue at green onset (HCM Ch. 31); counting every vehicle upstream let part of the "queue" still be driving in, and on the 350 m approach that read S 10 % low and lost the start-up measurement (1,333 against 1,472 veh/h/lane cars-only at scale 0.5). **S describes the regime, not the seed.** `calibrate_saturation_flow` always seeds itself with `CALIBRATION_SEED_FALLBACK`, never the run seed, and `calibrate_and_apply_webster` caches the result per regime key (speed scale, heavy ratio, movement engine and its signature) so a sweep measures S once. Reading the run seed made S a function of the seed -- 1887 veh/hr at seed 234 against 2338 at seed 764, a 24 % swing that moved the Webster cycle from 81.6 s to its 40 s floor and put two `config_hash` values inside one campaign, so the sweep's two halves benchmarked different signal plans. `tests/conftest.py` clears `main._saturation_cache` around every test; without that a cached S makes a later test's monkeypatched calibrator never run.

**Count vehicles by `vehicle.serial`, never `id()`.** CPython reuses a freed vehicle's address, so an `id()`-keyed set silently merges distinct vehicles: the cross-street counters read 147-150 against 168 actual and moved when unrelated allocations shifted. `Vehicle.serial` is a per-run ordinal restarted by `reset_traffic_generation`.

**A model that was never asked is not a model failure.** A provider timeout abandons its worker thread (an HTTP request cannot be killed) and that thread keeps the provider lock, so every tick behind it used to raise, be guarded into `HELD_ALL_OFF` and publish an all-off decision -- 611 of grok-4.6's 787 rejects in campaign 2026-09-22, a 98.6 % reject rate and `decisions_effective` 0 for an arm whose model was working. `agent.ModelBusyError` is raised by all three providers' lock acquisitions, propagates out of `ai_turn` instead of becoming an `INVALID` response, and `run_forever` records it as `SKIPPED_SLOW`: the grid point is counted and `decision.json` is left exactly as it was. Every other failure still fails closed.

**Signal timing follows the manuals, not literals.** `main.signal_change_intervals` sets yellow and all-red from ITE's kinematic formulas (`webster.ite_change_intervals`: Y = t + v/(2a), R = (W+L)/v, t 1.0 s, a 3.05 m/s², L 6.1 m, v the 85th-percentile car desired speed, W stop line to far box edge) bounded by MUTCD 4D.26 — 3.0 s + 3.5 s at speed scale 0.6, not the former 1 s + 1 s (`"signal_change_intervals": "legacy"` keeps those). Lost time is HCM's t_L = l1 + Y + AR − e per phase (`webster.lost_time_seconds`, e = 2 s); l1 is **measured** by the calibrator (time for the first four queued vehicles beyond four saturation headways, `startup_lost_source` says whether it was measured or HCM's 2 s default) and Webster's effective green is converted to displayed green G = g + l1 − e so the controller's real cycle equals Webster's. The calibrator drops headways above `CALIBRATION_INTERRUPTION_FACTOR` × median (an interrupted discharge is not a saturation headway, HCM Ch. 31). **Coordination** (`"signal_coordination": "coordinated"`, default): both nodes run the longer node's Webster cycle, re-split on their own flow ratios, Node B offset by the link travel time at mean car speed in `coordination_direction`; `SignalController.set_coordination` places each node in its cycle at reset and `_coordinate` compares every EW-green start with the master schedule and spreads the error over that cycle's greens within `COORDINATION_MAX_ADJUST_FRACTION` (20 %) — also TSP's recovery. Independent cycles (81.6 s vs 62.0 s on seed 234) drifted ~20 s per cycle. **Dilemma zone:** at yellow onset a vehicle inside its ITE stopping distance (`vehicle.ite_stopping_distance_px`) commits to go and is treated as facing green until the next green; beyond it, it stops. **Near-side turns (left-hand traffic) run with their green.** A "left" is the near-side turn: it never crosses the opposing stream, so it does not yield to it (an HCM permitted-left gap check was added and removed on 2026-09-23 -- that is a far-side turn in right-hand traffic, which this network does not model). It obeys the lamp like through traffic (no turn on red without a filter arrow, TSRGD 2016); it used to ignore the lamp and book the box whenever no *reserved* vehicle conflicted, and at 0.6x demand 30 of 61 turns entered on red across the cross street's green while the all-red waited for them (13 s median against 3.5 s). The same-approach corner-sweep conflict follows the model's own geometry (`SignalController._corner_sweep_conflict`): at the square-corner pivot a vehicle swings half its length either side of its lane centre, past the lane edge only when it is longer than `LANE` (a truck, a bus; never a car), and only into the adjacent lane -- so the starvation hold (`LEFT_TURN_STARVATION_FRAMES`) holds only through vehicles the waiting turner would sweep. Before, every turning car stopped every through lane of its approach. Sources admit per lane (`try_spawn_vehicle`: the first queued arrival whose lane is clear), not head-of-line: the head's blocked lane held arrivals bound for free lanes 29-99 % of the time. A far-node left positions for its turn right after the near node (`Vehicle.positions_for_turn`; the DBL-eviction exemption stays `needs_turn_lane`), a turner held at the bar for its lane books nothing, and one still out of lane 2 after `MISSED_TURN_HOLD_FRAMES` (10 s) goes straight (`SAFETY_COUNTERS["missed_turns"]`, summary `missed_turns_total`) -- cars sat 100 s+ in lane 0 before. Two stale-state leaks were closed with it: a yellow go-commitment now lapses once the vehicle has stopped short of the bar (a kept one booked the box on red), and `cancel_intersection_entry` clears an upstream vehicle's stored movement (a missed turn was judged as the old LEFT booking).

**Braking is bounded and what it cannot resolve is counted.** `_idm_step` never decelerates harder than the class emergency bound (`EMERGENCY_DECEL_MPS2`, SUMO vType defaults 9/7/7 m/s²); when that is not enough, the move is truncated at the leader's bumper or strictly short of the stop line (`STOP_LINE_EPSILON_PX` — a bumper exactly on the line stopped counting as upstream and entered the box on red, caught by `test_invalid_signal_values_fail_closed`), and `vehicle.SAFETY_COUNTERS` records it (mirrored into `network_throughput` as `ssm_*`, reported per vehicle-hour; TTC conflicts use FHWA SSAM's 1.5 s). Vehicles enter at `safe_insertion_speed` for the gap ahead (SUMO's insertionFollowSpeed) — full-speed entry was 36 % of IDM hard braking. Cooperative holds (behind a DBL bus, yielding to a bus's route merge) are a comfortable stop *now* under IDM; the bar logic used to turn them into a brake for a line hundreds of px away. A route-merge hold persists until the merge can happen.

**Perception is plan-then-commit.** `vehicle.index_frame(vehicles)` also snapshots every vehicle's (x, y, direction, speed) (`_take_snapshot`); every neighbour query reads `_seen(other)`, so car-following and lane-change perception are independent of update order (reversing the order used to move served passengers by up to 9.5 % and delay by 8.9 %). Reservations stay sequential. `tests/test_standards_conformance.py::test_car_following_does_not_depend_on_update_order`.

**Buses stop.** `bus_routes_config[route]["stops"]` (default: one far-side stop at each route's first node) with dwell = door time + max(boardings × t_b, alightings × t_a) from `global_config["bus_dwell"]` (TCQSM 3rd ed. Ch. 6 ranges; occupancy stays `BUS_PASSENGERS`, boardings and alightings equal in expectation). Dwells are drawn per (seed, route, trip index) by `main.draw_stop_plan`, so every arm sees identical dwells. A near-side stop sits `NEAR_SIDE_STOP_SETBACK_PX` short of the bar (outside the booking distance) and withholds TSP at that node until served (`near_side_stop_pending`). Telemetry publishes `dwelling` / `near_side_stop_pending`.

**Outputs a benchmark needs.** Every vehicle leaving writes a trip record (`main.tripinfo_record` → `logs/tripinfo.jsonl` → "Trip Info" sheet, unfinished vehicles appended at export — SUMO's tripinfo with write-unfinished); `fcd_period_s` > 0 writes floating-car data to `<workbook>_fcd.csv`. Summary columns add `network_saturation_flow_veh_hr_lane` / `network_to_calibrated_s_ratio` (HCM saturation headways measured at the stop bars in the running network), `geh_entry_*` (FHWA GEH, entered vs offered), latent demand and `signal_timing_json`; `print_campaign_summary` flags latent demand > 5 %, network S < 90 % of calibrated, GEH < 5 on < 85 % of sources, and states the runs needed per FHWA TAT Vol. III (`required_replications`). `tests/test_golden_regression.py` pins two canonical scenarios' complete end state; accept an intended change with `REPIN_GOLDEN=1` and commit the golden file with the reason — never re-pin to make an unexplained diff go away.

The baseline arm (`test_model == "None"`) must show zero decisions and zero TSP treatment: `agent.guard_baseline` turns any baseline or stale-arm turn into `OBSERVATION_ONLY`, `perform_full_reset` clears route flags for a baseline test, and `build_experiment_summary_row` raises `BaselineContaminationError` (the row is refused and the batch run marked `FAILED`) rather than export a contaminated reference row.

### Control strategy selector

The Single Run card picks the decider in two levels (`control_panel.CONTROL_STRATEGIES`): a **Strategy** dropdown — Baseline, Rule-Based, AI/LLM Assisted, AI/LLM Decided — and a **Decider** dropdown listing only that family's concrete deciders (`strategy_models`: `None`; `rule-based` / `passenger-pressure-tsp`; installed Ollama tags plus keyed API models for both LLM strategies), greyed out when the family has one. The two LLM strategies are the two control modes (`STRATEGY_CONTROL_MODE`: Decided = `"configured"`, everything else `"assisted"`), so choosing a strategy sets `ai_runtime["control_mode"]` — there is no separate mode toggle. `strategy_for(model, control_mode)` / `strategy_of(label)` are the inverse, and the batch model picker groups its checkboxes under the same four headings with a themed (`Modern.Vertical.TScrollbar`) scrollbar. Nothing downstream changed: `ai_runtime["model"]` still carries the one backend-neutral model string through `set_active_ai_model`, `ai_control.json`, the batch's `set_model` and every export column, so add a decider by adding it to `strategy_models`, never by teaching the agent or the exporter a family. The Batch Run card has no separate **Start test** button: a single timed run is a batch of one model x one seed, so it goes through the batch and gets the same export, summary row and pairing as every other arm (the batch still chains `request_start_test()` per run). Its **Stop batch** pauses the sweep in place (`batch_runtime["paused"]`; the run in flight is held with `is_paused` every tick, no next run starts, and the wall-clock timeout budget excludes the pause) and the button splits into **Resume** | **End**: Resume continues as if never stopped; End discards the run in flight and the queue (nothing is exported — a partial run has no summary row to pair), disarms the model and triggers the same full reset as RESET (`main.poll_batch_runner`).

### AI Configured (the model writes the timing plan)

`ai_runtime["control_mode"]` is `"assisted"` (the LLM requests TSP/DBL per route over Webster — everything above) or `"configured"`: the LLM owns the timing plan and the lane-2 flashers, Webster and the TSP state machine are off, and the paired DV is a different mechanism (never compare an assisted arm against a configured arm as decision quality; both pair against the Webster baseline). LLM deciders only: `set_active_ai_model` forces assisted for anything else, the panel exposes it as the **AI/LLM Decided** strategy, and a batch arm is labelled `<model> [decided]` (`CONFIGURED_ARM_SUFFIX`, `split_arm_label`) so one queue can mix modes; the internal mode value, the `control_mode` column and telemetry still say `configured`; `test_control_mode` is captured at test start and exported as the `control_mode` column. Every turn the agent (`agent.read_signal_map`, `signal_plan_prompt`, `guard.safe_signal_plan`) writes one `decision.json` of schema `signal_plan`: per node `ew_green_sec` / `ns_green_sec` (clamped 5–90 s by `guard.validate_signal_plan`), `end_current_green_now` and four `dbl` booleans, through the same single writer, `run_uuid`/`model`/turn checks and `merge_ai_decision` (which now takes `signals`; `step_simulation` publishes the live controller as `main._live_signals` so the `decide()` contract is unchanged). `SignalController.apply_plan` is the only entry: a plan sets `NodeState.plan_green_frames` (read by `get_green_time`, so telemetry's residual green follows it), applies immediately (a running green already longer than its new length ends this frame — through yellow and all-red, never skipping the intersection-clear wait), queues a cut that waits for `MIN_GREEN_FRAMES`, cancels TSP requests in flight and bypasses `_priority_update` while live; a plan is applied once per decision turn (`end_current_green_now` must not re-fire on every 30-frame merge). Fail-closed is Webster: a stale, foreign, invalid or other-mode decision, `HELD_WEBSTER` from the guard, disarming, or a full reset all `clear_plan()`. A commanded lane (`NodeState.dbl_commanded`) answers `is_dbl_active_for_approach` / `get_active_dbl_request` (a synthetic request with `commanded: True`, no bus) / `get_all_dbl_states`, so the canvas flashes it, buses merge into it (`is_dbl_requested_for_bus_leg` accepts it without a route flag; the bus-side obstruction/abandon rule still applies) and through-cars vacate — but unlike a bus-requested DBL it is shared with left-turners: `dbl_excludes_left_turns` is the gate `vehicle.py` and the spawner use, and a car that cannot slide out drives on instead of holding. Telemetry publishes `signal_state.plan`, `control_mode`, per node `dbl_commanded` and `left_turners_lane2`. `decisions_effective` counts a plan turn when the plan changed. `tests/test_ai_configured.py` covers the guard, the controller intervals, the merge refusals, the agent turn, the panel and a headless soak with a scripted proportional planner (`scripted_planner`, which also serves as the pattern for any non-LLM configured arm).

**Route flags are a continuous hold.** `SignalController._request_is_live` cancels a live request the frame its route flag drops (`FEATURE_DISABLED`) and suppresses that bus's leg for good, so `agent.check_locked` locks a route from the moment any of its buses has `priority_requested` (armed, waiting on the early-green gate) through `priority_granted`/`priority_clearing`, and `anti_cheat` re-imposes the live flags on locked routes for every arm. A decider only ever decides *new* requests. Locking only granted/clearing requests let every arm (rule included: 9 of 9 denials) withdraw most of its grants mid-approach as the snapshot changed; don't narrow the lock again. The snapshot lock still leaked (Run 8: 45 of 83 denials) through `STALE_DECISION`/`HELD_ALL_OFF` all-offs and requests raised after the snapshot, so the same lock is enforced at the merge boundary from the live controller: `main._set_ai_flags(flags, signals)` skips every route in `signals.routes_with_live_requests()`, including for `_hold_all_off` — fail-closed means no *new* treatment, a committed request finishes under the safety authority. The decision tick is 2–120 s (`control_panel.TICK_SECONDS_MIN/MAX`, clamped identically in `agent.read_ai_control`; a slider on both the Single Run and the Batch card) and defaults to `DEFAULT_TICK_SECONDS` (**10 s**) on both. It is set by the bus, not the slowest model: an entering bus reaches Node A's stop line ~39 s after entering (350 m at 9 m/s) and is inside the eligibility zone for its last 100 m (~11 s at the default), so 10 s gives it about four decision points on the approach and at least one inside the zone, where 60 s (the default until 2026-09-23) left many buses reaching A before any decision had seen them. (An earlier note here said the zone was 200 m and the bus in it "the whole way": the default zone is 100 m.) Flags are a continuous hold, so a long tick does not stop buses being treated -- it reduces the decider to a once-a-minute route switch. The agent skips-and-counts grid points that fall due during a call (`SKIPPED_SLOW`), so the tick must clear the slowest arm's p95 latency (kept local models: 0.7-1.7 s median, 2.0 s worst at the 8k context); `print_campaign_summary` names any arm that skipped more than `SKIP_RATE_TOLERANCE` (5 %) of its points (`_arms_skipping_decisions`), and `AGENT_CALL_TIMEOUT_CEILING_SEC` (45 s, pinned to agent.py's timeouts by `test_llm_control_loop`) bounds what one stuck call can cost: ceil(45 / tick) points. The former 50 s floor (timeout + margin) and its pre-batch warning are gone -- they protected against latencies the kept models no longer have. One fixed interval across every arm is part of the paired DV: in campaign 2026-09-22 a 3 s tick left phi3 issuing 118 of 300 decisions and nemotron 104, while gemini issued 299.

### Rule-based comparator (`rule_controller.py`)

Selecting the rule model name (`control_panel.RULE_BASED_MODEL`) in the same `ai_runtime["model"]` slot the LLMs use runs a deterministic conditional-actuated TSP/DBL rule instead of a model, through the exact same guard/decision/telemetry/export path — this makes rule-vs-LLM a clean paired comparison of decision quality, not mechanism. Keep any change to the LLM-facing schema mirrored here if it must stay a fair comparator.

### Max-pressure comparator

One more non-LLM arm sits in the same `ai_runtime["model"]` slot (`control_panel.NON_LLM_MODELS`; `rule_controller.is_rule_model` is true for all of them, gating the same no-latency/no-sampling/no-token handling): `passenger-pressure-tsp` (`control_panel.MAX_PRESSURE_MODEL`, `rule_controller.max_pressure_decision`; the old `max-pressure` name is still accepted) grants TSP when the bus approach's passenger pressure — queued pax plus the bus load, zero if its downstream is blocked — exceeds the cross street's, sharing the rule's DBL veto and per-node cap through `_decide`. The former `marl-q` tabular Q-learning arm was removed (2026-09-22); do not reintroduce an ML family without a trained, pinned policy. Max-pressure is deliberately the TSP *gate*, not a phase selector replacing Webster — every arm must keep the same mechanism for the paired DV to mean anything.

### LLM/rule decision auditing (State → Action+Reasoning → Outcome)

Every AI or rule turn is recorded to an **"AI Decision Audit"** sheet (`main.write_ai_decision_audit_sheet`, mirrored into the dashboard via `TelemetryDashboard._add_ai_decision_audit_sheet`), one row per decision, built from the *exact* telemetry snapshot `agent.py` used for that turn (`agent_turn_log.jsonl`'s `telemetry_snapshot` field) rather than a later or aggregated sample. Each row carries the decision's reasoning, requested/observed TSP and DBL routes, the full queue/passenger/network-summary/bus-distribution state at decision time, per-route load flattened into `route_vehicles_json`/`route_passengers_json` (`{route_id: buses_on_route}` and `{route_id: route_passengers_total}`, so the grant can be read against the load it was serving without parsing `route_states_json`), and an **outcome**: the same state fields captured at the *next* logged decision (or, for the final decision in a run, the nearest telemetry sample logged strictly after it) — `main._outcome_snapshot`. This lets a reviewer judge whether a grant actually helped without any new instrumentation. The separate, pre-existing **"LLM Performance"** sheet remains a lighter per-turn summary (latency/tokens/on-off counts only); it was intentionally left alongside the detailed audit sheet rather than merged, so existing consumers of its schema are unaffected.

`_add_ai_decision_audit_sheet` must never silently substitute on-disk `agent_turn_log.jsonl`/`telemetry_log.jsonl` for `decisions`/`telemetry_rows` a caller explicitly passed (or omitted) — an export meant to reflect only live/in-memory state (`export_llm_performance`, `export_summary_snapshot`) would otherwise leak in stale decisions from a previous run still sitting on disk. Only `export_all` (which explicitly reads and passes the session logs itself) is meant to see them.

## Working in this codebase

- Nodes are independent (`self.nodes[node_x]`) — never merge Node A/B state back into a shared clock. Never hard-code a node's x: use `canvas.INT_X[0]/[1]` (`control_panel.NODE_A_X/NODE_B_X`, `tests.helpers.NODE_A/NODE_B`); route waypoints, discharge plans, Webster splits, CSV `node_A_*/node_B_*` columns and the tests all derive from it, and `config_hash` includes the geometry so rows from different network lengths never pair.
- Change signal/right-of-way behavior only in `signal_controller.py`, together with the `vehicle.py` request contract; never let a vehicle or the LLM path set green directly.
- Change LLM-facing schema in `agent.py` and `guard.py` together, and check whether `rule_controller.py` needs the same change to stay a valid comparator. Keep `decision.json`'s internal route-ID-keyed format canonical.
- Change telemetry fields in `telemetry_exporter.py`, `telemetry_dashboard.py`, the agent minimap, and export mappings together, bumping `schema_version` for breaking changes.
- Preserve atomic writes (`os.replace` after a temp-file write) for every cross-process JSON file.
- Preserve START/RESET full-reset semantics and STOP's log/vehicle preservation — they have distinct, deliberate contracts.
- **One workbook per run.** `export_test_workbook` (timed tests, every batch run, and each checkpoint mark) sets `main._run_exported_workbook`; `perform_full_reset` clears it; the `atexit` `cleanup()` writes the session workbook only when it is still false. The session workbook's sheets are a strict subset of the test workbook's, built from the same JSONL logs, so emitting both just leaves a thinner duplicate. Don't make the exit export unconditional again.
- Always run the suite through `tests/pytest.ini` (`-c tests\pytest.ini`). Its `--capture=sys` is load-bearing, not cosmetic: pytest's default fd-level capture dup2()s fds 1/2 and swaps them per test, which dangles the standard channels Tcl binds once per process and makes a later `tk.Tk()` die inside its own startup (`couldn't read file .../init.tcl: No error`) on a random GUI test, about 4 runs in 10. Don't drop that flag or override it with `--capture=fd`. `tests/conftest.py`'s autouse `destroy_leftover_tk_root` sweeps up any root a test forgets to destroy, since a live root keeps its interpreter and pending `after` callbacks alive for every later test. Its autouse `isolate_runtime_files` points every `data/`, `logs/` and `results/` path constant of every module at a per-test temp directory: without it, a test calling `perform_full_reset` deletes the `logs/*.jsonl` of a simulator running in another process and one writing `ai_control.json` flips its agent to observation-only (three of the seven refused rows in the 2026-09-21 batch were the suite run mid-batch). Still, never run the suite while a batch is in flight.
- After a movement/signal change, run the full test suite plus a manual windowed run; check `traffic_state_telemetry.json` for the expected shape.
- **All** Webster timing readout lives in `telemetry_dashboard.py`'s Summary tab, not in `control_panel.py`: the "WEBSTER SIGNAL TIMING" card (`build_webster_timing_ui`) shows measured lane capacity plus, per node, condition (Optimal/Oversaturated/Unavailable), cycle length and demand ratio; the green split sits under each node's live signal-color indicator (`create_node_canvas`'s `green_time_label`). All of it is refreshed by `_refresh_webster_timing_labels`, driven by the telemetry poll. The control panel owns operator *inputs*; Webster output is observed state, so don't reintroduce a timing card there. `control_panel.get_webster_timing_summary()` stays the single source of truth both sides read.
